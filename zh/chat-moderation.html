视角 1

现实交易（RMT）机器人在四个服务器上跑同一条广告 — 而过滤器毫无反应

一条模板化广告 — 用真钱买高阶装备或 “300,900 Premium Gems”，并指向一个外部 “Inquiry Website: an external RMT site” — 被低等级、无公会、0 声望的机器人账号，在四个区域服务器的世界 / 区域 / 全体频道中反复张贴。自动过滤器毫无反应；靠玩家手动拉黑和举报。

机器人账号 A 在全体 / 世界频道张贴 RMT 广告 — “$49.99 = Premium Gem 300,900 (Inquiry Website: [external RMT site])”。一名玩家打开举报弹窗，选择了 “不当消息”。

同一个机器人账号出现在另一次会话中。举报者填写的理由是 “spamming link to spend money on another site”；该账号资料 — Lv.32、无公会、零声望 — 被标记为 “已举报”，而那条 RMT 广告仍清晰地留在后面。

视角 2

敏感词过滤器拦下了 “palabok” 和 “Buccees”，却从不说明理由

每一条被拒绝的消息都只返回同一个通用弹窗 — “该文本无法使用。” — 不提示是哪个词，也不说为什么。它按子串匹配，因此无害文本和脏话一并拦下，除了教会玩家怎么绕过它以外，什么也没教给玩家。

误报。 在一段无害的吃饭闲聊里，玩家打出 “palabok is a type of pan…”，过滤器用通用的 “该文本无法使用。” 把它拒掉了。

一条发给朋友的轻微脏话 — “damn lost connecttion :P” — 在私聊中被同一个通用提示拦下。连一对一私聊也在过滤范围内。

一次应当拦下的拦截（世界频道里的下流暗示 — 此处只作描述，不复现原文）。它返回的是和无害情形完全没有区别的同一个弹窗。

过滤器拦下了什么 — 大多拦错了对象

被拦文本频道判定
“damn lost connecttion :P”私聊勉强算合理 — 私聊中的轻微脏话应当拦下
“palabok is a type of pan…”世界误报 — 一道菲律宾面食误报
“Buccees”世界误报 — 一家美国加油站连锁品牌误报
“patrick mccaw”（NBA 球员）世界误报 — “mccaw” 中含有子串 “cock”误报
“Not for sale, ask someone else”（非英语）私聊（非英语）误报 — 一句普通的交易回复误报
“shit” / “ass” / “mf”世界 / 私聊应当拦下（有玩家连试 5 次）应当拦下
两重代价：正常聊天被拦下，玩家因此受挫；而由于提示是通用的，玩家干脆四处试探并绕过去 — 对那些真该拦的词，过滤器反而失效了。
视角 3

玩家举报的是刷屏而不是辱骂 — 而一句被空格拆开的歧视语过去了

两个结论。第一，举报 / 拉黑工具一直在被使用 — 但大多用在刷屏上：连归在 “不当消息” 下的消息也是 RMT 广告。第二，面对真正的辱骂，过滤器才是薄弱环节。

以 “不当消息” 提交 — 但来自机器人账号 B 的被举报内容，仍然是同一条 RMT 广告。

一起真实的骚扰案例 — 过滤器漏掉的那一类

在这次会话中，一名玩家在世界频道发布针对某一国籍的种族歧视言论，并把字母用空格拆开以绕过敏感词过滤。之后没有任何系统处置 — 其他玩家只是回一句，或者就此略过。冒犯性原文此处不予复现，仅作描述。

过滤器在屏幕上失效的三种方式

缺口屏幕上发生了什么
用空格绕过的歧视语有玩家用下划线 / 空格把歧视语拆开，消息就发出去了
脏话最终发了出去一句常见脏话在被拦下几次之后进了世界频道
骚扰被放任持续的敌意言论没有任何可见的系统处置；玩家只是默默拉黑，于是研发方永远听不到
缺口所在：过滤器对无辜的子串极其严格，却被任何一个把歧视语拆开写的人绕过，而且对持续骚扰不采取任何可见处置。举报分类没有把刷屏和辱骂分开，很多玩家又只是默默拉黑 — 于是真正的信号从来没有到达研发方。
