技术问题与体验阻力

在录制的玩家会话中看到的商店、购买与游玩流程阻力 — 这些拦路石从来到不了数仓。

关于这些画面。 画面是对录像中所观察到的时刻的复原图，屏幕上的文案经过轻微改写，并已本地化为中文。为保护匿名性，客户的真实录像不予公开。玩家自己输入的聊天内容按原文引用保留。
3.1

险胜之墙没有任何怜悯机制

屏幕上发生了什么：玩家打到一个有计时的章节 Boss，打得不错，却在 Boss 还剩 1–5% 血时输给了计时（“时间到” — 是伤害差距，不是被打死）。他重试，再重试。有些重试之间他会做升级（召唤、装备强化材料、宝石），有些之间则什么都不改。屏幕对如何补上这段差距只字不提：没有战力目标，没有伤害数值，没有任何该提升什么的提示。玩家看得出自己差得有多近 — 血条就摆在那里 — 但没有任何东西把它变成一个可以去追的数字，于是他原封不动地重打同一场，再以同样的方式失败。也没有任何过渡机制 — 没有累积增益，没有怜悯伤害加成，没有“你已经很接近了”的辅助。在连续 6–14 次险胜之后，这段过程会以三种方式之一结束：升级再重试的循环、转向低风险内容，或升级为在高价商店礼包上的花费。

放弃的标记：失败界面提供 Retry 和 Leave。玩家按下 Leave 而不是 Retry 的那一刻，会话的形态就变了 — 按 Leave 的玩家会转向低投入活动（世界 Boss 挂机、竞技场、休眠模式），而且往往不再回到那个 Boss。

在哪里看到：流失人群的墙横跨第 22–30 章外加成长副本；同样的结构出现在全新玩家（跳出人群）的第 2–5 章，以及分层 469 成员的第 7–31 章。

业务代价：这是录像里大多数流失弧线的起点（墙 → 花钱 → 没有回报 → 淡出）。一个怜悯 / 过渡机制可以一次性覆盖所有等级段。

实例：

  1. 第 23 章第 7 关 — 连续失败 11 次，其中三次以上 Boss 只剩 1% 血，始终没能突破。
  2. 第 25 章第 9 关（Boss D）— 一段时间内连续失败 14 次；两次尝试之间没有任何升级动作，仍在继续重试。
  3. 第 26 章（Boss F）— 失败 → 玩家按下 Leave，随后在设置里手动登出；这是录像中最清晰的放弃瞬间之一。
  4. 第 29 章第 11 关（Boss E）— 一名巨鲸档的流失玩家在同一堵墙上失败 3 次：花钱只是把墙挪了位置，并没有把它拆掉。
3.2

商店 bug：errorCode 9-100302 “商店中暂不可用”

屏幕上发生了什么：一名明显有付费意图的玩家打开一个真钱商品（高级宝石包、会员、限时优惠），走到结算，然后收到 “商店中暂不可用”（errorCode 9-100302）。在同一次会话内，这个错误会确定性地重复出现 — 同一个商品每次都失败 — 玩家会在放弃之前对同一个坏掉的商品重试 2–3 次。受影响人群中的购买跨越四种不同的店面货币 — 这不是单一店面的故障。

业务代价：这些是被挡在收银台前的愿意付钱的买家。数仓侧的规模参照：有 30,693 名玩家在其有史以来第一次成功购买之前出现过失败 / 取消的支付（§3.9）— 录像指出商店侧故障是其中一个原因。

实例：

  1. 有一名玩家在同一次会话中对同一个活动限时优惠发起了 3 次购买 — 每次都是同一个 9-100302 错误。
  2. 第二条引用 — 同一个错误出现在豪华会员、随后又出现在特别会员上 — 未通过复核：所引用的片段中根本没有出现该弹窗。此处列出它，是作为一条未成立的引用，而不是作为证据。
  3. 一个相关的供应商错误（9-100204 “供应商未初始化”）在成功转化和放弃的会话中都出现 — 成功的买家会顶着它重试，只是逛逛的人则就此停下；错误一样，需求状态不同。
  4. 在客户自定义人群上的旁证：一名分层 469 成员触发了一次激励广告购买，立刻收到 “无法购买” 错误（同一个阻断购买的错误家族）。
3.3

静默成功造成的信任 bug

屏幕上发生了什么：玩家完成了一次购买，界面却显示失败（错误码 100315、100107、100204-24001）— 而几分钟后，买到的物品照样进了邮箱。交易是成功的，界面却说失败了。

为什么重要：一个会谎报失败的支付流程，会教玩家不要信任商店。它可能训练出的行为 — 重复购买、申请退款，或干脆不再买 — 全是坏结果，而且在账单数据里一个都看不见（订单行看上去很正常）。

实例：

  1. “失败”界面（错误码 100315 / 100107 / 100204-24001）之后，物品在同一次会话中进入了邮箱 — 界面说失败，交易却完成了。
  2. 在退出信号人群中对同一错误家族的独立发现：churn 玩家最后几次会话的结算过程中出现支付错误 9-100315 / 10-100107。
3.4

会说谎的广告错误

屏幕上发生了什么：玩家把一条激励广告完整看完 — 游戏却弹出 “广告没有加载出来。”。在最清晰的一段片段里，错误浮层留在一个成功的 “已获得物品” 弹窗后面：游戏一边声称广告失败，一边把奖励发了出去。另一段里，一次尝试产生了双重错误 — “由于跳过了广告，无法领取奖励”（红）加上 “广告没有加载出来”（黄）— 而这只是一次观看。跳过还会被单独惩罚，直接拒发奖励。

为什么重要：激励广告是非付费玩家的主要资源管道（问题 7）。谎报玩家刚刚做了什么的错误，正在侵蚀那条让非付费玩家继续推进的闭环的可信度 — 而且它们集中出现在最接近流失的时刻（失败之后、领奖之时）。

实例：

  1. 广告肉眼可见地播完了 → “广告没有加载出来” 照样弹出。
  2. 自相矛盾的双重状态：错误浮层留在一个成功的 “已获得物品” 弹窗后面。
  3. 一次尝试上的双重错误：“由于跳过了广告，无法领取奖励” 与 “广告没有加载出来” 同时出现；商业化视角还抓到一次流程中途的 “由于跳过了广告，无法领取奖励” 拒发奖励 — 玩家选择了重试而不是放弃。
3.5

服务器等待的层层叠加

屏幕上发生了什么：“正在等待服务器响应” 模态框出现在可预测的关卡口 — 登录、战斗菜单、组队匹配、好友列表、公会界面、公会攻城、批量召唤、竞技场切换。这个模态框在锁住输入的同时，游戏世界仍在下面继续运行。等待会叠加：有一名玩家在 2 分钟内撞上 4 个模态框。

为什么重要：单次等待都不致命，致命的是叠加。而且它落在参与度最高的界面上（公会、竞技场、召唤）— 正是留住社交型玩家的那些内容。

实例：

  1. 同一名玩家在 2 分钟内连续遇到四个 “正在等待服务器响应” 模态框，每次输入都被锁住。
  2. 在完全流失的玩家身上，各个 UI 层都观察到了等待 — 登录、战斗菜单、组队匹配、公会、好友。
  3. 一名流失玩家在第 23 章连续失败五次，期间服务器浮层不断叠加 — 墙的阻力与服务器的阻力在同一段时间里叠在一起。
3.6

Boss 失败之后紧接着的 “你的会话已过期” 崩溃

屏幕上发生了什么：玩家连续两次输给章节 Boss，然后 — 就在他最沮丧的那一刻 — “你的会话已过期” 弹了出来，加载界面卡死，这段游玩就此结束。重新登录后，又是一次服务器等待。在四个相互独立、各自经过验证的人群中都看到了这一现象，因此它是一个模式，而不是偶发。

为什么重要：这次崩溃正好落在最接近流失的时刻（连续 Boss 失败）。对好几位被拍到的玩家来说，它是会话溶解进休眠模式或断线之前，最后一件有意义的事。

实例：

  1. 在 Boss C（第 22 章）连续两次失败 → 会话过期崩溃 → 加载界面冻住，这段游玩结束。
  2. 同一堵墙，不同人群：在第 22 章 Boss C 上反复以微小差距失败，最终在一名流失玩家的最后几次会话中以会话过期错误告终。
  3. 一名小额付费档玩家的会话，在险胜之墙加上一次会话过期错误之后，塌陷成了挂机。
  4. 旁证：“你的会话已过期” 造成的冻结在分层 469 成员的会话中反复出现。
3.7

落在最依赖广告的那批玩家身上的广告闭环阻力

屏幕上发生了什么：不付费的玩家在五个触点上（商店货币、免费召唤、Quick Hunt、Daily Ad Booster、跳过计时）每次会话连看 5–10 次以上激励广告 — 广告是他们的主要资源管道。而在这个闭环里：“跳过”的广告被拒发奖励、广告冷却封锁、广告加载失败 — 与此同时，买了去广告礼包的玩家完全不用交这份税。而广告库存本身就是竞品营销：40 多款竞品在玩家最沮丧的时刻被展示，每段广告时长 15 秒到 3 分钟不等。

为什么重要：这个闭环把阻力精准地集中在唯一没有钱包替代方案的那一群人身上 — 游戏中最脆弱、最容易流失的人群 — 并用竞品的安装广告把他们的沮丧变现。

实例：

  1. 一名流失的非付费玩家在一次会话中观看了大量其他游戏的全屏广告，在一条“被跳过”的广告上被拒发奖励，随后又撞上广告冷却封锁 — 而同一人群中买了去广告的玩家完全跳过了这一切。
  2. 广告时长从 15 秒到约 3 分钟不等，几乎每条广告都带跳转商店的结束卡；录像中拍到一次点进竞品商店页面的操作。
  3. “广告没有加载出来” 失败连续出现 3–4 次，挡住了付费人群玩家那个零门槛的商业化触点。
3.8

竞技场的 “无法生成推荐” bug

屏幕上发生了什么：玩家打开竞技场 — 这是推进主线任务的前置条件 — 而匹配始终加载不出来：游戏 “无法生成推荐。”。屏幕上没有任何绕开的办法。玩家在主线上被硬卡住，在会话中途提交了一张游戏内客服工单，最终登出。基线预期：竞技场应当对每一个已解锁它的玩家正常加载。

在哪里发现：分层 469 — 来自客户自有玩家分层体系的前五大人群；每一段片段都已证实属于分层 469 的成员。

为什么重要：与问题 1–7 不同，这一个直接中断了主进度线 — 这是唯一一个被拍到的、让玩家完全无法继续游戏核心循环的缺陷。它还产生了本次试点中最清晰的玩家主动证据：一张在镜头前提交的客服工单。建议的规模评估步骤：调取错误状态日志，统计有多少玩家被卡住、在哪些服务器上、持续了多久。

实例：

  1. 竞技场推荐列表生成失败 → 主线任务被挡住 → 会话中提交客服工单 → 登出。
  2. 同一批经过验证的素材中，相邻的支付时刻展现出它周围的阻力质感：一个月度金币礼包被带到支付弹窗后又取消；一次同伴木桩的尝试因钻石不足被挡住。
  3. 有好几次分层 469 的会话是在支付确认弹窗仍留在屏幕上时结束的 — 会话在结算中途溶解掉了。
3.9

数仓对这一切能看到什么（对照）

账单 / 埋点能显示的 它无法显示的
30,693 名玩家在其首次完成购买之前出现过失败 / 取消的账单订单（7 月 1 日–8 月 15 日，全量人群）；最大单一市场 = 60.7%（18,635） 没有原因，没有错误码，没有屏幕 — 无论是商店 bug、玩家主动取消，还是一次静默成功，失败行看上去完全一样
存在 purchase_failure 埋点事件 它们不携带任何商店 / 商品 / 道具上下文 — 483 个事件中的 483 个（100%）：究竟是哪一个商品失败了，根本没有被埋点
问题 1、4、5、6、7、8 完全没有数据 墙、说谎的广告错误、服务器等待、崩溃、广告阻力以及竞技场封锁，在数仓里完全没有留下任何痕迹（授权范围内不存在任何客户端错误 / 体验 / 埋点表）
